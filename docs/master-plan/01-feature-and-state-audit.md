## How the interface connects

`src/app/**/page.tsx` maps each path to `OpsApp(initialScreen)`. `OpsApp` creates `OpsRuntime`, `RouteSync`, `OfflineBridge` and a `ScreenBoundary` around `AppFrame`. `OpsRuntime` extends `OpsProvider`, which extends the verbatim `OpsEngine`; its only business override currently replaces simulated bazaar synchronization. All screen and sheet values still originate in `OpsEngine.renderVals()` and its `ordersVals`, `bakeVals`, `invVals`, `groceryVals`, `bazaarVals`, `pnlVals`, `adminVals`, `recipeVals`, `queueVals`, `miscVals` and `custVals` methods.

`OpsVals` is the interface between that engine and the mechanical template port. Screens receive the same large value object. Navigation is engine state plus `history.replaceState`, not independent Next route data loaders. The authenticated sign-in form is separate from this engine. No identity/bootstrap adapter connects a verified signed-in profile to the engine's default owner role in these application components. Data persistence is the engine's local/session-storage snapshot, plus IndexedDB mirroring for bazaar sales. Successful local mutations are not evidence of corresponding database writes.

The engine core passed the prototype contract check. Operational overrides belong in a subclass or a separate adapter, never in `src/store/engine/ops-engine.js`. `OpsRuntime` does preserve existing sync phrases; future messages must report real persistence outcomes before emitting the signed-off success strings.

## Apple, keyboard and state acceptance

These are **verification requirements**, not browser-compatibility claims established by this static audit. Current Playwright configuration does not test WebKit, and emulated WebKit is not proof of iOS Home Screen behavior.

1. Test at minimum iPhone portrait 320/375/390/430 logical pixels, landscape with keyboard shown, iPad portrait/landscape and split view, and Mac Safari at 1280 and 1440. Use the same approved mobile/tablet/desktop composition; verify no content or action escapes the viewport, scroll container or safe area.
2. Verify first visit, installed PWA, reload, hard refresh, deep links, browser back, engine back, page close/reopen, foreground/background, network loss/restoration, offline cold launch after install and session expiry. `RouteSync`'s use of replaceState must not be confused with a complete browser history stack.
3. Test all text and numeric fields with iOS software keyboard, decimal punctuation, pasted formatted quantities, autofill, phone/email fields, long names/notes and large text. Current form labels are incomplete in some sheets, some search fields use placeholders alone, and most control fonts are below 16 px; verify actual Safari focus/zoom behavior rather than assuming it.
4. Test VoiceOver and hardware keyboard through every sheet and quick-add overlay: initial focus, name/role/value, tab containment, dismissal, return focus, error association, selected state of toggles/tabs, and announcement of sync/undo status. Do not disable screen-reader interaction because the normal workflow is touch.
5. Most primary controls are 44 px or larger, but exceptions include the 26 px reconciliation tick (`payments.tsx:55`), 30 px notification dismiss (`notifications.tsx:59`), 28 px channel switch (`notifications.tsx:75`), 32/38 px shell close controls (`app-frame.tsx:340`, `app-frame.tsx:598`) and 42 px navigation buttons. Quantify hit-area/spacing compliance before any visually visible change.
6. Verify CSS reduced-motion behavior and the engine counter/tilt code with the OS setting enabled. Existing `globals.css` and `E:2029`/`E:2061` already respect reduced motion in several paths; preserve that coverage.
7. Verify proof selection from Photos/Files/camera, portrait/orientation behavior, HEIC/JPEG/PNG handling under the approved upload policy, interrupted upload retry, signed proof URL expiry, replacement and a real owner's readable proof view.
8. Verify Safari downloads/Files/share behavior for exports and complete restoration on a clean profile. CSV export alone is not a full recoverable system backup. With one launch sales device, designate its writer identity and prove queue recovery before lending/replacing/clearing that device.
