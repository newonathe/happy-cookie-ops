# MP-06l — erasure function resolution and execute authority

Status: bounded local acceptance passed, 2026-09-25. MP-06 and G1 remain open. This fixes the reproduced SQL error and API-role grant only; it does not decide legal retention policy, create an erasure UI, or authorize a hosted database change.

## Verified trigger and scope

[MP-06i](MP-06i-plan.md) reproduces `anonymise_customer(text,text)` failing SQLSTATE 42883 for an active authenticated owner: `digest` is installed in the managed `extensions` schema, but the function's trusted search path excludes it. The current public function ACL also grants EXECUTE to PUBLIC and anon, although the body permits only an active owner. Applied migrations are protected. The latest local migration before this slice is `20260101002500_bff_cleanup_fair_claims.sql`.

Use one forward migration `20260101002600_erasure_digest_authority.sql`. Preserve the existing function identity, parameters, return type, security definer, trusted search path, owner and anonymization/deletion statements. Replace only the unqualified `digest` call with `extensions.digest`. Revoke EXECUTE from PUBLIC and anon; preserve authenticated and service_role execution. The body currently raises default SQLSTATE P0001 when a non-owner crosses the authenticated execute boundary; do not silently claim those calls are ACL-level 42501 denials.

One focused rollback-only SQL fixture `tests/integration/security/erasure-authority.sql` must prove: anon 42501 before body execution; active helper, support, inactive owner and missing profile fail the current owner check without any data or erasure-log change; active owner processes synthetic unpaid and confirmed orders, leaves the financial record anonymized, removes the unpaid order, writes the expected `extensions.digest` phone hash, and returns the exact count. Use forged JWT role claims as a negative control, and verify grants, protected function metadata and fresh-connection absence after rollback. No real customer data enters the fixture.

Register the suite in `scripts/test-db-security.py`, including its expected unique case count, one deliberately restored unsafe anon grant, and `erasure_requests` in empty-fixture checks. Update `tests/fixtures/function-authority.json` only for the reviewed ACL/body fingerprint delta after a fresh local reset; never loosen the drift guard. Root owns plan/state/evidence and final integration. One bounded Codex Sol/high worker owns only the migration, SQL fixture and security-runner wiring; root independently reviews and runs the disposable database, manifest update, Python guards, pinned `pnpm verify`, continuity and exact cleanup. No Claude, remote Supabase, UI/UX, prior-migration edit, commit, push or deployment in this slice.

Because fixture runners pin the reviewed migration set, root also updates their exact version/count guards from 26 to 27 while retaining explicit checks for the prior cleanup migrations. The affected local-only harnesses are `test-db-bootstrap.py`, `test-auth-fixture.py`, `test-cleanup-recovery-rpcs.py`, `test-pages-provider-fixture.py`, `test-session-repository.py`, their count-only wrapper receipts and the focused auth fixture guard. This is a source/version consistency update, not a weakening to arbitrary migration counts.

Stop if the extension schema/owner or digest signature differs, if the replacement changes unrelated function attributes, if the denied calls mutate rows, or if a fresh reset reveals a different business-rule dependency. Hosted Supabase behavior remains a separate G1 gate.
