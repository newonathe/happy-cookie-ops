# MP-07a — local route and demo hydration repair

Status: local slice verified on 2026-09-20; **MP-07 and G1 remain incomplete**. This slice repairs the ported demo runtime's direct routes without editing locked screens, shell, copy, styles or the protected engine. It does not supply the real session/data initialization coordinator required for launch.

## Trigger and implementation

- Direct `/sales` reproduced as `/` because RouteSync wrote the engine's temporary Home screen to the address bar before the requested route committed. The first URL-write effect now waits for the requested view screen.
- `/stocktake` previously rendered an empty content area: the engine has a route key but the locked frame renders counting inside Inventory. RouteSync maps that URL to the existing Inventory view, retains `/stocktake` until a later in-app navigation, and handles the alias on `popstate`.
- After a stocktake pause, Home rendered while the address remained `/stocktake`. The engine context is a stable class instance, so RouteSync was not notified of subsequent state changes. Subscribing to the changing render-values context lets URL updates track navigation. The stocktake pause/reload/resume test catches this regression.
- Browser Back and Forward had no route entries because every screen change used `replaceState`. RouteSync now pushes an indexed history entry with a bounded snapshot of the prototype's screen stack. On `popstate` it restores that stack without calling the engine's forward-navigation method; otherwise a subsequent app Back went forward. The interaction test mixes Orders → Inventory → native Back/Forward → native Back → app Back → native Back/Forward, and checks URL, visible content, restored stack and stable runtime identity on all three browser profiles. It does not prove every selected-ID transition.
- Independent Terra/medium review found a second navigation class: `startBatch` changes the protected engine's screen directly without incrementing `navTick`. RouteSync now recognizes a screen-key change as navigation too. The added user-action test starts production on `/bake`, proves the tick is unchanged, then uses native Back/Forward between Bake plan and Production focus. It passes on all three CLI browser profiles. Batch completion and draft/history semantics still require the real coordinator.
- A fresh-build Home could pass while the same static prerender failed with React 418 after clock drift. The demo engine constructs visible timestamps independently at build/server and browser module evaluation. OpsApp now mounts the unchanged runtime after the first client render, so the server and hydration pass agree. A one-week browser clock shift reproduced the failure before this change and passes afterward.
- The Sales log is intentionally read-only. Its route assertion now requires a concrete fixture sale instead of a nonexistent button. E2E fixture setters await React's state-commit callback, which removes a real observation race for batch and selected prerequisites.

## Remaining MP-07 acceptance and product risk

The mount gate prevents the demo clock mismatch by serving no operational screen HTML until JavaScript runs. The generated `/` and `/shop` HTML each have **zero `data-screen-label` elements**, checked in the current `.next/server/app` output. This temporary tradeoff is **not final public storefront rendering**: the real bootstrap must provide a deterministic initial snapshot and remove the blank prerender gate while keeping the approved screen UI. The direct-route matrix covers 25 operational paths, not the separate sign-in page, and uses fabricated fixtures and emulated browsers. It does not prove physical iPhone/macOS Safari, hosted Cloudflare refresh/hydration, role authorization, selected order identity in real data, all app-level Back controls, all draft states, responsive viewport ownership, or release accessibility/performance.

The history tests cover one ordinary three-screen chain, the app's Back button, and starting a bake; they do not certify batch completion, long history chains, browser restoration after process termination, drafts/sheets, or protected selected-ID navigation. The history marker retains at most 64 screen keys; final history semantics belong with the real coordinator. Real session/data coordination, role gates and ID routing depend on MP-08 authority and MP-06 projections. Offline sale durability remains a separate MP-18–21 blocker. Keep MP-07 `in_progress` and do not deploy or claim G1 readiness from these local tests.
