## Required durable record

A dedicated private session table has: session_hash (64lowercasehex primary key), user_id, provider_session_id, csrf_token (43canonicalbase64url), encrypted token envelope, credentials_version, refresh_fence, lifecycle state, created_at, absolute_expires_at, refresh_lease_until and optional revoked_at/cleanup status. Only a narrow trusted BFF infrastructure path accesses it. No anonymous/authenticated CRUD, no cookie plaintext, no provider-token plaintext, no generic table/RPC proxy. Server-generated identifiers and expiration are not taken from browser input. Preserve8hour absolute lifetime and independent CSRF generation from the reviewed handler contract.

Before any read/acquire/finalize: require active public profile, bound auth.sessions.user_id equality, and `(auth.sessions.not_after IS NULL OR auth.sessions.not_after > clock_timestamp())`, in addition to local expiry and non-revocation. A surviving provider row alone is insufficient because cleanup can lag expiry. Provider inactivity/global session policies and account ban/delete behavior still require actual provider acceptance; do not claim these checks reproduce every Auth rule. No stale profile projection grants a business command: user-JWT RLS and active capability must be checked transactionally by each command.

## Fixed transaction operations

1. Create: only after verified Auth user/provider-session binding, generate/hash cookie and CSRF, encrypt version0credentials with session/user/version AAD, and insert once under authoritative database time. Do not return a cookie before acknowledged durable insert. An uncertain insert may create an unreachable session; it cannot authorize a browser until acknowledged and must expire or be cleaned safely.
2. Read: lookup by hash, validate all local/provider/profile conditions, return only the bounded record to the server authority. Browser response is the MP08b projection. Access JWT expiry does not make repository read fail when a permitted explicit refresh is needed.
3. Acquire refresh: transactionally lock the row, validate authority, reject an existing live lease, increment monotonic fence and record a finite lease using database time. Never reacquire an expired uncertain refresh just to reuse the old token. Prefer reauthentication unless a separately verified provider recovery protocol exists.
4. Finalize refresh: authenticate returned user and provider session identity; require equality with the existing binding. Under row lock recheck profile/provider/local status, absolute expiry, current fence and unexpired lease. Store the new envelope/version atomically without extending absolute expiry or changing routine cookie/CSRF. A stale worker cannot finalize/release another fence. If the response is lost, an acknowledged later read must observe either the prior state or the complete committed state, never partial credentials.
5. Revoke: atomically mark local state revoked before provider cleanup. Revoked rows can never be read/acquired/finalized as active, even while cleanup is pending. Remote failure returns503, not a logout acknowledgment; later reads still fail closed. Cleanup retains only restricted encrypted material until acknowledgment/expiry. Deletes or backup restores must not reactivate an old cookie.
